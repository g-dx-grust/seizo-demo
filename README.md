Figmaで設計した製造ダッシュボードの動作モック。バックエンドなし・フロントのみ・メモリ上のstateのみで動作します。

## 起動

```bash
npm install
npm run dev
```

→ http://localhost:5173 （`/dashboard` にリダイレクト）

- デスクトップは **1440px幅固定** レイアウト。プロジェクター投影時はブラウザ幅を1440px以上に
- モバイル画面（`/m/*`）はスマホベゼル風フレームで中央表示。トップバー右の「モバイル」ボタン ⇄ フレーム上の「デスクトップ版へ」で相互に行き来できます

## 承認連動デモ（商談の見せ場）

1. `/m/approvals/po-2660`（M2）で **「承認する」**
2. トースト「承認しました。Larkで申請者へ通知されました」
3. M1: カードが対応済みタブへ移動、承認待ちバッジ **5→4**
4. K-1088 の数値が全画面で連動:
   - 利益率 **13.4% → 12.1%**（02テーブル・03詳細・09ガントKPI）
   - 実際原価 **10,220 → 10,378** ／ 差異 **+1,370 → +1,528** ／ 材料費 2,140 → 2,298

**リセット**: キーボード `R` または右下の「デモをリセット」ボタン（承認state・CSV取込stateの両方が初期化されます）。

## CSV取込デモ（データ連携の見せ場）

「APIで基幹システムと繋げない会社でも、CSVだけで運用開始できる」ことを見せる画面です。

1. サイドバー「データ取込」（または生産計画・実績の赤バナー／通知センター「再連携する」）→ `/import`
2. 赤バナー「製造実績（生産C00）が未連携です」→ **「今すぐCSVで再連携」**
3. ウィザード4ステップ: ファイル選択 → プレビュー・列マッピング → 検証 → 完了
   - **「デモ用サンプルCSVを使う」ボタンで進めてください**（実CSVは取り込めないため。実ファイルを選択しても「サンプルデータでプレビューします」と注記した上でフローは進みます）
   - 検証ステップで「212行中210行OK・警告2行（品番未登録→仮登録、欠損→0補完）・エラー0」の演出
4. 取込完了 → 以下が連動:
   - `/import`: C00行が「たった今・正常・取込済み」、KPI未連携 1件→0件、取込履歴の先頭に追加
   - 生産計画・実績: 赤バナー →「連携済み（8/16分 210行）」緑バナー
   - 通知センター: 「生産C00 前日データ未連携」→「連携済み」表示
5. 他のCSVソース（受注・案件／購買／日報／品質／マスタ）も同じウィザードで取込デモ可能
6. 「CSVフォーマット定義」カードの**テンプレートダウンロードは実際にCSVファイルを保存**します（クライアント生成・オフライン動作、UTF-8 BOM付きでExcelでも文字化けしません）

### データソースの根拠（一志精工電機様 提案書準拠）

データソース10種は、提案書（`/Users/shojiyuya/Documents/Codex/2026-07-24/10-1-2026-7-10-2/index.html`、2026.07.27版）の「既存システム資産」に合わせています:

- **生産C00系5種** — 受注・生産計画／発注・購買／製造実績（23:00バッチ）／売掛・買掛／マスタ類。C00の実メニュー名（受注処理・計画処理・実績処理・売掛買掛処理）とマスタ名（品番・金型管理・得意先・製品金型対応・単価・原価マスタ）をそのまま使用
- **JupiterX 1種** — 設備の稼動/準備/待機/停止＋電力kW（5分刻み）。提案書どおり「データをダウンロード(CSV)」出口からの自動取得という説明
- **Excel帳票3種** — 日報（工数補完）／見積・工数単価（チャージレート台帳）／検査記録
- **バーコード1種** — 作業工数（読取率96.2%、指示書準拠）

CSVの列定義は提案書の横断キー「**製番・品番・金型コード・工程コード・設備コード・日時**」を使用。「データ品質チェック」カード（欠損・重複・突合・更新遅れ）は提案書のG-DX基盤アーキテクチャ図と、ヒアリング課題05「取得データが正しいか検証できていない」への回答です。サイドバーにはテナント名として一志精工電機株式会社を表示しています。

## Figmaとの差分メモ（指示書優先で実装）

- Figma MCP未接続の環境で実装したため、指示書のデザインシステム＋データ仕様を正とした（指示書2章の指定どおり）
- 01 経営サマリーの詳細数値はFigma（node 2:77）を取得できないため、共通データ（年度売上14.4億・稼働率71.3%・K-1088利益率13.4%・粗利率24.1%など）から矛盾しないよう構成
- 指示書内の軽微な不整合: 04の顧客別内訳合計は1,487百万円だが見出しは「年度累計14.4億」→ 表示は指示書どおり「14.4億」を採用
- M1承認待ちの「外注発注 追加ワイヤーカット加工820千円」と、昨日の通知「外注発注を承認:山口精機(820千円)」は指示書どおり両方表示（同一案件に見えるが仕様記載を優先）
- モバイル下部タブは「ホーム／実績入力／承認（赤バッジ）／通知」の4項目とし、通知タブはデスクトップの通知センターへ遷移

※デモ用サンプルデータ。実在企業名は指示書記載の架空名＋仕入先例（ミスミ・THK等、指示書記載分）のみ。
